# 📊 Схема работы бота

## 🔄 Процесс проверки чека:

```
┌─────────────┐
│ Пользователь│
│   отправляет│
│   PDF чек   │
└──────┬──────┘
       │
       ▼
┌──────────────────────────────────┐
│  Telegram Bot (bot.py)           │
│                                  │
│  1. Проверка доступа             │
│     ├─ Владелец? ✅              │
│     └─ В allowed.json? ✅/❌     │
│                                  │
│  2. Проверка файла               │
│     ├─ Тип: PDF? ✅              │
│     └─ Размер < 10MB? ✅         │
│                                  │
│  3. Загрузка файла               │
│     └─ Download PDF bytes        │
└──────┬───────────────────────────┘
       │
       │ POST multipart/form-data
       │
       ▼
┌──────────────────────────────────┐
│  Datagrab API                    │
│  https://api.datagrab.ru/        │
│  upload.php?key={API_KEY}        │
│                                  │
│  Анализ чека:                    │
│  • Проверка подлинности          │
│  • Парсинг данных                │
│  • Детекция модификаций          │
│  • Проверка структуры PDF        │
└──────┬───────────────────────────┘
       │
       │ JSON Response
       │
       ▼
┌──────────────────────────────────┐
│  Обработка ответа                │
│                                  │
│  result:                         │
│  ├─ "forbidden" → ❌ API ключ   │
│  ├─ "unpaid" → ❌ Подписка      │
│  ├─ "error" → ❌ Ошибка         │
│  ├─ "fake" → ❌ Подделка        │
│  ├─ "mod" → ⚠️  Пересохранен    │
│  ├─ "unrec" → ❌ Не распознан   │
│  └─ "tbank/sber/..." → ✅       │
│                                  │
│  Форматирование:                 │
│  • Эмодзи статусы                │
│  • check_data → таблица          │
│  • Timestamp → дата/время        │
└──────┬───────────────────────────┘
       │
       ▼
┌──────────────────────────────────┐
│  Отправка пользователю           │
│                                  │
│  ✅ Чек Т-Банка                  │
│                                  │
│  📋 Результат проверки:          │
│  Банк: tbank                     │
│  Профиль: 1                      │
│                                  │
│  💳 Данные чека:                 │
│  Отправитель: Иван И.            │
│  Получатель: Петр П.             │
│  Сумма: 1000 ₽                   │
│  Статус: Успешно                 │
│  ...                             │
└──────────────────────────────────┘
```

## 🔐 Система доступа:

```
┌────────────────────┐
│   Любой юзер       │
└────────┬───────────┘
         │
         ▼
    ┌─────────┐
    │ /start? │────→ ✅ Справка (всем)
    └────┬────┘
         │
         ▼
    ┌──────────────┐
    │ PDF файл?    │
    └────┬─────────┘
         │
         ▼
    ┌──────────────────────┐
    │ Проверка доступа:    │
    │                      │
    │ user_id == OWNER_ID? │
    │        ├─ ДА → ✅    │
    │        └─ НЕТ ↓      │
    │                      │
    │ user_id in allowed?  │
    │        ├─ ДА → ✅    │
    │        └─ НЕТ → ❌   │
    └──────────────────────┘
             │
         ✅  │  ❌
             │   └─→ "У вас нет доступа"
             │
             ▼
      Проверка чека
```

## 👥 Управление пользователями:

```
    OWNER (OWNER_ID)
           │
           ├─→ /allow 123456
           │   └─→ allowed.json: [123456]
           │
           ├─→ /allow 789012
           │   └─→ allowed.json: [123456, 789012]
           │
           ├─→ /revoke 123456
           │   └─→ allowed.json: [789012]
           │
           └─→ /list_allowed
               └─→ "📋 Разрешенные: 789012"

    User 789012
           │
           └─→ PDF файл → ✅ Проверка

    User 111111
           │
           └─→ PDF файл → ❌ "Нет доступа"
```

## 🎯 Сценарии использования:

### 1. Первый запуск:
```
1. Владелец запускает бота
2. /start → видит команды
3. Узнает свой ID: @userinfobot → 123456789
4. /allow 123456789 → добавляет себя
5. Отправляет PDF → проверка работает ✅
```

### 2. Добавление клиента:
```
1. Клиент пишет владельцу
2. Клиент узнает ID: @userinfobot → 987654321
3. Владелец: /allow 987654321
4. Клиент отправляет PDF боту → работает ✅
```

### 3. Удаление доступа:
```
1. Владелец: /revoke 987654321
2. Клиент отправляет PDF → ❌ "Нет доступа"
```

### 4. Мониторинг:
```
1. Владелец: /list_allowed
2. Бот: "📋 Разрешенные:
   • 123456789
   • 987654321"
```

## 🚀 Производительность:

- ⚡ Асинхронная обработка (aiohttp)
- 📦 Лимит файлов: 10 МБ
- ⏱️ Timeout API: 30 секунд
- 🔄 Polling режим (можно переключить на webhook)
